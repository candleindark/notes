# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal notes repository. Notes are Markdown files organized into topic subfolders (e.g. `ai_usage/`). There is no application to build, and no test suite — the only code is the README-tree tooling described below.

## README is generated — do not hand-edit the tree

`README.md` contains a note index between the `<!-- TREE:START -->` and `<!-- TREE:END -->` markers. Everything between those markers is regenerated by a script; edits there will be overwritten. Edit text *outside* the markers freely.

Regenerate after adding, renaming, moving, or retitling a note:

```bash
python3 scripts/generate_readme_tree.py
```

`scripts/generate_readme_tree.py` walks the repo, renders each `.md` note as `[<title>](<path>)` grouped by folder, and rewrites the marked region. Key behaviors to keep in mind when writing notes or changing the script:

- Only the contents of **subfolders** are indexed; Markdown files at the repo root (e.g. `README.md`, `CLAUDE.md`) are intentionally not listed.
- A note's displayed title is its **first level-1 heading** (`# ...`); if a file has none, the title falls back to the file stem. Start each note with an `# H1` to control how it appears in the index.
- A folder's heading is its name title-cased with separators turned into spaces (`ai_usage` -> `Ai Usage`); see `folder_title`.
- These directories are skipped entirely: `.git`, `.idea`, `scripts`, `.github` (see `EXCLUDED_DIRS`).
- The script exits non-zero if the markers are missing from `README.md`.

## CI

`.github/workflows/update-readme-tree.yml` runs the generator on push to `main` and PRs targeting `main`, then commits the regenerated `README.md` back to the triggering branch. Assumes all branches/PRs originate from this repo (not forks).

The workflow declares `permissions: contents: write` for itself; the repo's *default* workflow token is intentionally left read-only. Keep that split — grant write at the workflow/job level rather than flipping the repo-wide default.

The auto-commit message includes `[skip ci]` to avoid re-triggering the workflow.
